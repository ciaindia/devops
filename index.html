1. DevOps Basics

What is it? DevOps is a set of practices combining software development (Dev) and IT operations (Ops).

Why is it used? To shorten the development lifecycle and provide continuous delivery with high quality.

Key Terms
  • CI (Continuous Integration): Automatically building and testing code on every commit.
  • CD (Continuous Delivery): Code is always in a deployable state.
  • Continuous Deployment: Every change passing tests is automatically deployed to production.
  • Infrastructure as Code (IaC): Managing infrastructure through machine-readable definition files.
  • Monitoring & Logging: Tracking system health and recording events.
  • Containers & Cloud: Packaging apps (Docker) and running them on rented servers (AWS, GCP).
Plan → Code → Build → Test → Release → Deploy → Operate → Monitor
Interview Tip DevOps is not a tool; it's a culture and methodology focusing on automation and collaboration between Dev and Ops teams.

4. IP Address Classes

Important Note Class A, B, and C are historical classful IPv4 categories. Modern networks primarily use CIDR (Classless Inter-Domain Routing). Beginners encounter these terms often, but they are obsolete.
ClassRangeDefault MaskCIDR
Class A1.0.0.0 – 126.255.255.255255.0.0.0/8
Class B128.0.0.0 – 191.255.255.255255.255.0.0/16
Class C192.0.0.0 – 223.255.255.255255.255.255.0/24

CIDR Examples:
10.0.0.0/8 (16 million+ IPs)
172.16.0.0/12 (1 million+ IPs)
192.168.0.0/16 (65,536 IPs)
192.168.1.0/24 (256 IPs, common in home networks)

5. Private IP Addresses

What is it? IP ranges reserved for internal networks (LAN/VPC) that cannot be routed on the public internet.

Private IPv4 Ranges
  • 10.0.0.0/8 (10.0.0.0 - 10.255.255.255)
  • 172.16.0.0/12 (172.16.0.0 - 172.31.255.255)
  • 192.168.0.0/16 (192.168.0.0 - 192.168.255.255)

Example: Your home router might be 192.168.1.1 and your laptop 192.168.1.100.

Interview Tip A Private IP is used inside a local network. A Public IP is assigned by an ISP and is visible on the internet. NAT (Network Address Translation) allows private IP devices to access the internet using a single public IP.

6. Localhost

What is it? A hostname that means "this computer". It resolves to the local loopback address.

localhost → 127.0.0.1 → current machine
Example Accessing http://localhost:8080 is exactly the same as accessing http://127.0.0.1:8080 on your own machine.
127.0.0.1 vs 0.0.0.0
  • 127.0.0.1: Local loopback address. Only accessible from inside the machine itself.
  • 0.0.0.0: Represents "all IPv4 interfaces" when a server binds to it. Accessible from the outside network.

7. Ports

What is it? A logical endpoint. While an IP identifies the machine, a port identifies the specific service running on it.

Why is it used? To allow one machine to run multiple services (web server, database, SSH) simultaneously.

IP + Port = Socket Example: 192.168.1.10:8080 (IP is 192.168.1.10, Port is 8080)
Interview Tip A port is not an application itself. A process/service listens on a port. If a port is "in use", another process is already listening there.

8. Hosts File

What is it? A local file that maps hostnames to IP addresses manually, bypassing DNS.

Locations:

  • Linux/Mac: /etc/hosts
  • Windows: C:\Windows\System32\drivers\etc\hosts
Example 
127.0.0.1    myapp.local
192.168.1.20 server.local
myapp.local → hosts file lookup → 127.0.0.1 → local machine

Test it with: curl http://myapp.local

Interview Tip The OS checks the hosts file before querying the DNS server. It is highly useful for local testing before deploying DNS records.

9. DNS (Domain Name System)

What is it? The phonebook of the internet. It translates human-readable domain names into IP addresses.

example.com → DNS Resolver → DNS Server → 93.184.216.34 (IP address)

Common Record Types:

  • A record: Maps a name to an IPv4 address.
  • AAAA record: Maps a name to an IPv6 address.
  • CNAME: Maps a name to another domain name (alias).
  • MX: Mail exchange record for routing emails.
  • TXT: Text records, often used for domain verification and security.
Commands 
nslookup example.com
dig example.com
host example.com

Why is it used? To track code changes, collaborate, and maintain history.

Code → git add → git commit → git push → GitHub

12. Docker

What is it? A platform to develop, ship, and run applications inside isolated environments called containers.

Why is it used? "It works on my machine" → Docker ensures it works everywhere identically.

Browser → localhost:8080 → Docker Host Port 8080 → Container Port 80 → Nginx
Important Commands 
docker build -t myapp .
docker run -d -p 8080:80 nginx
docker ps
docker stop <container_id>
docker logs <container_id>
docker exec -it <container_id> sh

13. Dockerfile

What is it? A text file with instructions on how to build a Docker image.

Example Dockerfile 
FROM nginx:alpine
WORKDIR /usr/share/nginx/html
COPY . /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
  • FROM: Base image.
  • WORKDIR: Sets the working directory inside container.
  • COPY: Copies files from host to container.
  • RUN: Executes commands during the build process.
  • EXPOSE: Documents the port the container listens on.
  • CMD: Default command executed when container starts.

14. Docker Compose

What is it? A tool for defining and running multi-container Docker applications using a YAML file.

Why is it used? Instead of running 5 long `docker run` commands, you define everything in `docker-compose.yml`.

Nginx + Prometheus + Grafana + Loki + Alloy → defined in docker-compose.yml
Commands 
docker compose up -d
docker compose ps
docker compose logs -f
docker compose down

Interview Point: Docker Compose automatically creates a default network, allowing services to communicate with each other using their service names as hostnames.

15. Nginx

What is it? A high-performance web server, reverse proxy, and load balancer.

Browser → Nginx (Reverse Proxy) → Internal Application (e.g. Node.js on port 3000)
Basic Configuration 
server {
    listen 80;
    server_name example.com;
    
    location / {
        proxy_pass http://localhost:3000;
    }
}

16. GitHub Actions

What is it? GitHub's native CI/CD platform.

Why is it used? To automate software workflows (build, test, deploy) triggered by GitHub events.

git push → GitHub Actions triggers Workflow → Checkout → Build → Test → Deploy
Key Terms
  • Workflow: Defined in .github/workflows/cicd.yml.
  • Job: A set of steps executing on the same runner.
  • Step: Individual task (script or action).
  • Runner: The server that runs your workflow.

17. Self-hosted GitHub Runner

What is it? Your own machine/server configured to run GitHub Actions jobs instead of using GitHub's cloud instances.

Why is it used? For accessing private network resources, custom hardware, or saving costs.

GitHub → Workflow Event → Self-hosted Runner (Your Server) → Local Docker Executes Job
Interview Tip A self-hosted runner executes jobs on your infrastructure. Therefore, the runner process can execute local Docker commands directly on that host machine.

18. Prometheus

What is it? An open-source systems monitoring and alerting toolkit built on a Time-Series Database (TSDB).

Why is it used? To scrape, store, and query metrics (CPU, Memory, HTTP requests).

Application Exporter → Prometheus (Scrapes targets periodically) → Grafana
Exporters Small binaries that expose application metrics in a format Prometheus understands (e.g., Node Exporter for Linux stats).

19. Grafana

What is it? An open-source analytics and interactive visualization web application.

Why is it used? It connects to data sources like Prometheus and Loki to build beautiful dashboards and alerts.

Prometheus (Metrics) → Grafana Loki (Logs) → Grafana

Interview Point: Grafana itself does not collect data. It queries and visualizes data stored in external backends (Data Sources).

20. Loki

What is it? A horizontally scalable, highly available log aggregation system inspired by Prometheus.

Why is it used? Traditional log systems index full text. Loki only indexes labels for logs, making it extremely lightweight and cost-effective.

Container Logs → Alloy → Loki → Grafana

21. Grafana Alloy

What is it? Grafana's vendor-neutral observability collector (OpenTelemetry native).

Why is it used? It replaces multiple agents (like Promtail). It collects metrics, logs, and traces, and forwards them to backend systems (Prometheus, Loki, Tempo).

Docker Logs/Metrics → Alloy → Loki / Prometheus
Interview Tip Alloy is primarily a collector agent. It is not just a logging equivalent of Node Exporter; it acts as a universal pipeline for all telemetry data.

22. Monitoring and Alerting

What is it? Observing system state and reacting to anomalies.

  • Metrics: Numeric measurements over time (CPU at 90%).
  • Logs: Discrete event records (User login failed).
  • Alerts: Notifications sent when thresholds are breached.
Application → Metrics → Prometheus → Grafana → Logs → Alloy → Loki → Grafana → Alerts → Grafana Alerting System (Email, Slack)

23. Terraform

What is it? An IaC (Infrastructure as Code) tool by HashiCorp.

Why is it used? To provision and manage cloud infrastructure using declarative configuration files (.tf).

Terraform → Cloud Provider API (GCP/AWS) → Provisioned Infrastructure
Core Commands terraform init: Initialize working directory.
terraform fmt: Format code.
terraform validate: Check syntax.
terraform plan: Show execution plan.
terraform apply: Apply changes.
terraform destroy: Delete infrastructure.

Interview Point: Terraform uses a terraform.tfstate file to map real-world resources to your configuration. State management is crucial.

24. GCP (Google Cloud Platform)

What is it? Google's suite of cloud computing services.

  • Project: Logical grouping for all resources.
  • VPC: Virtual Private Cloud (your isolated network).
  • Compute Engine: Virtual Machines (VMs).
  • IAM: Identity and Access Management (permissions).
Terraform → GCP → VPC → Compute Engine VM → Ubuntu OS → Docker → Nginx

25. Ubuntu Server

What is it? A popular Linux distribution for servers.

Administration

df -h                # Check disk space

SSH Keys: Instead of passwords, use cryptographic key pairs (public/private). Private key stays with you; public key goes on the server (~/.ssh/authorized_keys).

26. End-to-End Project Architecture

Bringing it all together in a modern DevOps pipeline:

Developer → Git commit → GitHub ↓ GitHub Actions triggers CI/CD ↓ Self-Hosted Runner (running on VM) ↓ Docker builds and runs the container ↓ Nginx serves the HTML Website

Observability Stack:

  • Monitoring: Docker → Prometheus → Grafana
  • Logging: Docker → Alloy → Loki → Grafana
  • Cloud Infrastructure: Provisioned via Terraform on GCP.

30. Troubleshooting Scenarios

Practical steps when things go wrong.

Scenario: Website not opening (Port 8080)
  1. Is container running? docker ps
  2. Is port listening? ss -tulpn | grep 8080
  3. Check container logs: docker logs <container>
  4. Test locally from server: curl http://localhost:8080
  5. Check Nginx status: systemctl status nginx
  6. Check cloud firewall / security groups allowing port 80/8080.
  • Docker container not starting: Run docker logs or start it interactively without detached mode (remove -d) to see stdout immediately.
  • Port already in use: Find PID with ss -tulpn and use kill <PID> if safe.
  • DNS not resolving: Check nslookup <domain> or edit /etc/hosts.
  • Cannot SSH: Ensure port 22 is open, SSH service is running, and your private key permissions are secure (chmod 400 key.pem).
  • GitHub Actions failure: Click the failed step in GitHub UI and read the output logs.
  • Self-hosted runner offline: SSH into VM, check the run.sh script or journalctl if it runs as a service.
  • Prometheus target down: Check http://target_ip:9100/metrics via curl. Check firewall rules.
  • Grafana cannot connect to Prometheus: Ensure Prometheus URL is correct in Data Source settings (e.g., http://prometheus:9090 in Docker network).
  • Loki logs not appearing: Ensure Alloy is running, checking its own logs, and that timestamps are correct on host machines.
