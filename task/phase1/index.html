Product Requirements Document

DevOps Local CI/CD, Monitoring & Logging Platform
Objective: Build and host a simple HTML website locally using Docker Desktop, with automated GitHub CI/CD, monitoring using Prometheus and Grafana, and centralized logging using Loki and Grafana Alloy.

1. Project Overview

The project demonstrates a complete local DevOps workflow starting from source-code development and GitHub version control through automated CI/CD deployment, container monitoring, logging, and alerting.

4. Functional Requirements

FR-01: Website

The system shall provide a simple responsive HTML website.

  • Home section
  • About section
  • Services or Projects section
  • Contact section
  • Responsive CSS styling

FR-02: Dockerization

The website shall run inside a Docker container using Nginx.

  • Create a Dockerfile
  • Use an Nginx base image
  • Copy website files into the Nginx web directory
  • Expose port 80
  • Run the service using Docker Compose

FR-03: Docker Compose

Docker Compose shall manage the complete local environment.

Expected services:

  • Nginx
  • Prometheus
  • Grafana
  • Loki
  • Grafana Alloy

8. Monitoring with Prometheus

Prometheus shall collect infrastructure and application metrics.

  • Container availability
  • CPU usage
  • Memory usage
  • Container metrics
  • Nginx metrics where available

Prometheus shall be accessible locally at: http://localhost:9090

9. Grafana

Grafana shall provide dashboards for metrics, logs, and alerts.

  • CPU usage
  • Memory usage
  • Container status
  • Application metrics
  • Application logs

Grafana shall be accessible locally at: http://localhost:3000

Grafana Alloy shall collect container logs and send them to Loki. Grafana shall provide an interface to search and view the logs.

11. Alerting

Basic Grafana alerts shall be configured for important system events.

  • Website or container is down
  • High CPU usage
  • High memory usage
  • Container restart
  • Nginx errors

13. Non-Functional Requirements

  • The website should load quickly on the local machine.
  • Services should restart automatically when configured.
  • Configuration must be maintained in GitHub.
  • The entire environment must be reproducible.
  • A developer should be able to start the environment using:
docker compose up -d

16. Success Criteria

  1. Developer pushes code to GitHub.
  2. GitHub Actions automatically starts.
  3. Local self-hosted runner executes the workflow.
  4. Docker image is built successfully.
  5. Website is deployed automatically.
  6. Website is available at localhost:8080.
  7. Prometheus collects metrics.
  8. Grafana displays dashboards.
  9. Alloy collects container logs.
  10. Loki stores logs.
  11. Grafana displays searchable logs.
  12. Grafana alerts work for basic failures.
  13. The environment can be recreated using Docker Compose.
